内核结构变化

  • concat(kn_deq, kr_fp) → kv_up [tile_len, 576] BF16 全程物化

过程要点

被设备硬拒

内核结构变化

  • pypto.view(q_reshape, [8,128,128]) = 256KB GM 窗口 ＞ 192KB UB 预算
  • permute → reshape → matmul → permute（4 步，含 3 次布局搬运）
  • nope 权重对完整 w_uk 做 4096KB 视图
  • 128 头拆成 4 组 × 32 头，每组 view 仅 64KB
  • transposed_batchmatmul × 4，permute 链由算子内部折叠为 1 步
  • 权重切分移到 host wrapper，kernel 直接消费 4 个预切片张量

过程要点

门禁连起点都拒
静态可行性闸门判定起点内核自身不可行（256KB 视图超预算 + cube mL0=8 未 16 对齐），共拒绝 12 次。这逼着搜索走向结构重构 —— 任何保留原 view 结构的候选都被整体否掉。
粒度扫描已扫穿
num_groups（RoPE 头维分组）单峰：32 组 176.84 最优，64 组 200.70、16 组 194.86；再往外 8 组 363.36、4 组 586.82 急剧恶化；2 组 UB 溢出、128 组编译失败。
融合受阻
想把 down_proj 与 kv_proj 融合（F-21）不可行：两者分处不同 loop 是刻意的活跃性边界（合并会重新污染 q_rope_out，那是第 4 轮 debug 的正确性修复），且输出 dtype 不同（FP32 vs BF16）无法用一个 matmul 表达。
瓶颈未解
AIC 60.7% → 77.6%，但 AIV 21.8% → 23.2% 几乎没动，谓词停顿 77.6% → 76.4%。收益来自把已经忙的流水线压得更满，闲置的 vector 通道始终没被利用。

跨算子：哪些手段真的有效

有效 · 消除中间量
把 concat / assemble / permute 链从 kernel 里去掉，是本次收益最大的单一手法。ds_v32 拆掉 [tile_len,576] 拼接拿到 22%，mla_prolog 用 transposed_batchmatmul 折叠 permute 链拿到第二段收益。
有效 · 按预算反向切割结构
UB 预算 192KB 是硬墙。mla_prolog 把 128 头切成 4 组后视图从 256KB 降到 64KB，不仅解决自身超限，还解锁了此前被门禁整体拒绝的一大批 tile 动作。
有效 · 提高任务粒度
flash_attention_mha 只把 Q_TILE 128→256 并同步放大 cube tile，就拿到 1.20× —— 单位评估收益最高。但这类收益有明确天花板：一旦 L0A / UB 触顶，同一轴上再调只会回归。
无效 · 单纯粒度扫描
flash_attention_mha_grad 沿 S1/S2_TILE 与 unroll_list 两条轴试了 140–180 次组合，可行配置只有 2 个且都回归；更大的 tile 触精度门，更大的 unroll 直接 OOM。
无效 · 合并向量子图
ds_v32 把 4 趟反量化向量 pass 合成一个子图，实测比最优值更慢。合并子图不减少工作量，只打乱调度。
硬墙 · 精度与 dtype
多处优化卡在不可逾越的约束上：ds_v32 的 int8→FP32 直转被设备拒绝；flash_attention_mha_grad 的 S2_TILE=896 触发精度门（max_error_ratio 0.0049 > 0）；mla_prolog 的 down_proj / kv_proj 因输出 dtype 不同无法融合。

四个算子的瓶颈分布

三个算子的最优画像都指向同一个结论：被推高的是已经繁忙的通道，闲置的通道没被利用。ds_v32 与 mla_prolog 的 vector 通道长期闲置（AIV ≈ 15–23%），flash_attention_mha 与 _grad 则卡在 cube 与 vector 之间的串行递归。四个算子拿到的增量，本质上都是把同一段串行链压得更紧，而不是打散它。
