# 算子性能泳道板 · Lab Tour 实物道具

一块空泳道板，加 15 条长短不一的 Task 条，条上还能插芯片托盘那套 tile 小方块。
参观者自己把 Task 往泳道里摆，摆完抬头看右边空出多少格 —— 讲解员再说「编译器会排成 25 格」。

这是继芯片托盘之后的第二件道具。托盘讲的是「有很多核」，泳道板讲的是
**「这些核大部分时候没排满」**。两件 0.6 比例下都是 252 x 180 的外廓，摆在一起是一套。

```bash
node generate.js --scale 0.6          # 默认，产出 stl/ 目录
node plan.js     --scale 0.6          # 产出 plan.svg，A3 横
```

## 三件东西

| 件 | 1:1 设计 | 0.6 打印 | 说明 |
|---|---|---|---|
| 泳道板 x1 | 420 x 300 x 14 | 252 x 180 x 8.4 | 2 条 AIC + 4 条 AIV，道长 35 格 |
| Task 条 x15 | 18/12/9/7/4 格，各 3 条 | 长 108/72/54/42/24，宽 18.5，高 12 | 一格 = 10 mm（0.6 下 6 mm） |
| tile x48 | 15 立方 | 9 立方 | **与芯片托盘的 tile 是同一个件** |

**分三盘打**：板一盘，15 条 Task 一盘（`bars-all.3mf`，222 x 117 mm），
48 个 tile 一盘（`tiles-all.3mf`，87 x 87 mm）。

已经打过芯片托盘的话，那 40 个 tile 直接拿来用，只需补 8 个。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--scale` | `0.6` | 0.05 ~ 2 |
| `--out` | `stl/` | 输出目录 |
| `--bed` | `256` | 床面边长，只用于判断要不要切块 |
| `--margin` | `2` | 每边要留的空地。见下方「为什么只留 2 mm」 |
| `--split` | `auto` | `1` / `2` / `4`，把板切成几块 |

## 选哪个比例

| 比例 | 板 | 最长 Task 条 | 用料 | 场合 |
|---|---|---|---|---|
| 0.5 | 210 x 150 x 7 | 90 x 15.3 x 10 | 约 110 g | 小床面，或者要多做几套 |
| **0.6** | **252 x 180 x 8.4** | **108 x 18.5 x 12** | **约 190 g** | **默认。与芯片托盘同宽，桌上是一套** |
| 1:1 | 420 x 300 x 14 | 180 x 31.3 x 20 | 约 889 g | 板必须 `--split 4`，四块拼 |

## 直接用 3MF

`stl/` 下的 `.3mf` 打开即是拼好的对象，耗材号已指定：

| 文件 | 1 号 | 2 号 |
|---|---|---|
| `board.3mf` | 本体 深灰 | AIC 道底 白色 |
| `bars-all.3mf` | 15 条 Task 蓝色 | — |
| `bar-18u.3mf` 等 | 单种长度 蓝色 | — |
| `tiles-all.3mf` | 48 个 tile 蓝色 | — |

Task 条和 tile 都是单色的，直接打。

板没有 AMS 也能打：白色只在 `z = 2.4 ~ 3.0`（0.6 下 `1.44 ~ 1.8` mm）这一条**整齐的 Z 向色带**上，
也就是泳道槽底最上面那层，切片里加一次「打到某层暂停换料」即可。因为不需要擦料塔，
板才能做到和托盘一样宽。

## 备用分色 STL

板：`board-1-body.stl` / `board-2-aic.stl`，导入后各自指定颜色，位置已对齐，不要移动。
Task 条：`bar-18u.stl` 等 5 个，单色，直接用。
tile：`tile.stl` 一个，自己复制 48 份（或直接用 `tiles-all.3mf`）。

## 打印方向与参数

**板平贴热床、泳道朝上打，不要旋转，零支撑。** 导出时已经是打印姿态。

| 项 | 值 | 为什么 |
|---|---|---|
| 层高 | 0.2 | |
| 顶面层数 | **6 层以上** | 板面（z=14）是 191 cm² 的大顶面，压在 42 层之上，顶层太少会起波纹 |
| 底面层数 | 3 | |
| 填充 | 25% gyroid | |
| brim | **关** | 0.6 下板是 252，256 的床每边只剩 2 mm，放不下 |
| 热床 | 65 度 + 光面板 | 不开 brim 时压住翘边全靠它 |

Task 条平躺打，坑朝上，零支撑。tile 就是个立方体，怎么摆都行。

### 为什么只留 2 mm

`--margin` 默认 2，是刻意的：板要和芯片托盘同宽（0.6 下都是 252 x 180），两件摆在一起
才是一套。代价就是 256 床面每边只剩 2 mm，不能开 brim。托盘已经按这个尺寸打过。

不想冒这个险，把 `--margin` 调到 10，生成器会自动把板切成两块（缝落在第 16 格的刻度上，
不碍事）；或者直接用 `--scale 0.5`。

## 为什么是这些尺寸

**6 条道（2 AIC + 4 AIV）。** 真实芯片是 24 AIC + 48 AIV，道具保住 1:2 的比例但不复刻
72 道 —— 72 道的话 15 条 Task 一人一道就摆完了，没有「排不排得紧」这回事。6 条道、
15 条 Task，平均每道两三条，摆法才有好坏之分。

**Task 条长度是倒推的。** 18/12/9/7/4 各 3 条、合计 150 格，刚好能在 6 条道上排成
每道 25 格的完美解：18+7 三道、12+9+4 三道，六道齐平。道长给到 35 格，所以最优解排完
右边空出 10 格 —— 占道长 28.6%，刻意贴近真实数据里「28.3% 的时间同时只有 ≤2 个 Block
在跑」那个数。随手摆通常落在 27 到 30 格，没人会摆到放不下，不至于卡住参观者。

**板厚 14、底板只有 3。** 槽底那 242 cm² 的顶面压在 9 层之上，默认底 3 + 顶 4 已经盖满，
中间没有稀疏填充层，不会塌 —— 这是芯片托盘的盖子用一次失败换来的教训。刚度全部交给
道间那 5 宽、11 高的筋，和注塑件薄壁加筋是一个路数。

**条高 20、槽深 11。** 条落进槽里还露出 9（0.6 下 5.4 mm），捏得住。配合间隙恒为每边
0.35 mm，**不随比例缩放** —— 换比例不用重调松紧。tile 与坑用的是同一套口径，所以
**tile 和 Task 条必须按同一比例打印**。

**tile 坑每 3 格一个，不是每 2 格。** 坑边长 16.17（比 tile 每边大 0.35），每 2 格排下来
两端只剩 1.9 的壁（0.6 下 1.15 mm）—— 参观者往里按 tile 时就是从那儿裂。每 3 格排，
端壁 6.9、坑间筋 13.8，踏实得多。代价是坑少了，条上的坑数变成 6/4/3/2/1，15 条共 48 个。
坑深 6（0.6 下 3.6），tile 高 15（0.6 下 9），露出 9 —— 捏得出来，又不会一碰就倒；
坑底以下还有 14（0.6 下 8.4 mm）实料。

## 怎么用（5 分钟）

1. 空板推给参观者，15 条 Task 倒在旁边：「这是一个算子的所有任务块，六个核，摆摆看最快多久。」
   （tile 先别拿出来，一上来就给 48 个小方块只会让人忙着摆积木。）
2. 他们摆完，拿红笔或一根筷子压在最右端，读刻度：通常是 27 到 30 格。
3. 翻到平面图视图四：「编译器排 25 格。差的这几格，就是手写调度和编译器的差距。」
4. 指最短那三条：「每块任务不管多小，都要先交一笔启动开销。真实数据里 AIV 的启动
   吃掉了 18% 的核时 —— 碎任务越多，这笔越疼。」
5. 这时候再抓一把 tile 插进某条 Task 的坑里：「每个 Task 其实是在啃这些数据块 ——
   托盘上那些小方块，就是这些。」条越长坑越多，数据量和时间的对应关系就摆在那儿。
6. 收尾指回芯片托盘：「托盘上是 72 个核。这块板只有 6 条道，72 条的时候谁来摆？」

第 5 步不必把 48 个坑填满，插三五个够了 —— 5 分钟的场子经不起摆积木。

左侧 6 个浅坑是贴标签用的，自己写 AIC0 / AIV0…，或留空让参观者自己定义。

## 模型里有什么、没有什么

**有**：泳道槽、道间加强筋、上下两条时间轴刻度（每格一短刻、每 5 格一长刻）、
左侧标签坑、AIC 道底的白色色皮、15 条 Task 条、条顶面每 3 格一个的 tile 坑（共 48 个）。

**没有**：文字（所有标注靠贴纸或平面图）、Task 之间的依赖关系、核内 L1/L0/UB 的层次、
Setup 启动开销（条上不再有任何表示）、AIC 与 AIV 的差异（真实数据是 Setup 占比 2.2% 对 18.0%）。

后两条是刻意的取舍：15 条通用 Task 条可以摆进任何一条道、正反都能放，参观者不会卡在
「这条该怎么摆」。Setup 和 AIC/AIV 的差异留给讲解和 Perf Lane Kit 的屏幕演示。

## 几何口径

尺寸的唯一来源是 `geometry.js`，`generate.js` 和 `plan.js` 共用。改尺寸只改那一处。
tile 的边长直接 `require('../chip-tray-prop/geometry').TILE`，两件的口径不可能走偏；
3MF 写入也复用隔壁的 `lib3mf.js`。挪动目录会立刻报错，而不是悄悄对不上。

数据口径来自 `Design/perf-lane-kit/data/example.json` 的 rank0：
72 核 = 24 AIC + 48 AIV；窗口 4823.6 us；86 个 Task、4038 个 Block；
AIC 的 Setup 占核上占用 2.2%，AIV 占 18.0%；28.3% 的时间同时只有 ≤2 个 Block 在跑。

**尚未实际打印验证。** 已做的检查：8 个 STL 全部零退化面、零奇数边；板的 261 个长方体与
每条 Task 的 5~15 个长方体都零重叠、零悬空底面；首层 100% 实心；tile 与坑每边 0.35 mm；
穷举确认 6 道最优跨度就是 25 格。用料与工时按体积估算，不是实测。
