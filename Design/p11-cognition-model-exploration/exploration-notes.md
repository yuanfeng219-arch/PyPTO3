# P11 · 同一坐标，连续切片

P9 让听众看到同一个对象如何换视角，P10 让听众看到如何换观察范围。P11 把两段操作收成一张心智图：**围绕同一次计算，横向换视角，纵向换粒度。** 点选示意对象 A01 可以亲手验证横向联动；纵向转场保留同一个菱形锚点，让观众从头到尾都知道该追哪一个对象。

## 1. 选择连续切片

| 编排思路 | 对象连续性与空间辨识 | 投影与讲述取舍 |
|---|---|---|
| A：完整三圆复制后重排 | 轮廓匹配直接，但多个同权重的完整模型会争夺视线，容易被理解成三个计算实例。 | 横向传播有冲击力，重复标签占空间，讲述者要额外解释副本的身份。 |
| B：从原模型衍生连续切片 | 同一菱形、同一三色拓扑和一条连续引导线，把新形体绑定到原模型。切片从源点开始就弱化细节。 | 原件仍是视觉主语。左右分开的切片为转场留出运动距离，可以在文字退出后继续靠形态讲述。 |

主实现选 B。视觉语言借用「测量截面」：轮廓刻线为形体提供参照，斜纹标识观察视角的共同区域，截面内的规整采样标记和取景框说明观察范围。保留了 A 的横向传播，没有复制整套图标和文字。右侧是图解，左侧是讲话者的两句提示，页底是验收用播放控件。

## 2. 第一幕：先存在，再建立关联

- **0–1.65 s**：Graph 上、Assignment 左下、Pipeline 右下。三圆环绕固定的 Paged Attention 锚点。不同相位的约 3 px 漂移及约 1.6 px 半径变化让观察面有轻微呼吸。
- **1.65–5.4 s**：三圆沿各自方向向内收敛；呼吸逐渐归零。斜纹由两个视角的真实 SVG 裁切共同决定，只有几何重合处才出现。
- **5.3–9.1 s**：计算 × 数据、计算 × 时间、数据 × 时间出现引注。三枚菱形标记与 A01 同源；自动演示一次联动，然后保留可点选入口。点击 A01 暂停演示并锁定三个响应，再点击解除。
- **语义边界**：A01 是示意 ID，只说明同一对象可以在不同视角被追踪。圆内图元不代表真实任务数、依赖、硬件配置或执行时间。正式资料中可核实的 Task 48 未被替换成 A01 的数据来源。

## 3. 转场：从同一坐标抽出截面

**9.05–12.65 s**，两个简化切片错峰从中心锚点衍生到两侧，原件略向左上腾挪并缩小。曲线贯穿三个锚点；复制出来的是观察截面。**13.15–17.8 s**，原件向上落到 Device，高度居中的左切片移到 AI Core，右切片从更低的弧线收进 Iteration。每组椭圆沿着各自路径变形：三圆横向对中、纵向压缩，轮廓和锚点全程存在。曲线引导逐渐交给纵轴。画面使用 SVG 正投影式截面，无透视相机、旋转或斜向消失点。

## 4. 第二幕：让范围逐层收敛

**约 18 s**，Device、AI Core、Iteration 三层就位。截面宽度收窄；组内仍保留 Graph 蓝、Assignment 绿、Pipeline 橙。圆点、格点、短线分别标记三种观察视角，列数减少表现取景范围收敛。层宽和纹理是图解编码，无物理比例或计量含义。

当前范围由取景框、锚点和对应引线共同强调。纵轴上的亮线跟着定位十字向下推进，留下从 Device 经 AI Core 到 Iteration 的来路。**24 s** 停在 Iteration。点右侧引注可在三个聚焦层级间定位；它们不会打开新页面或相互替换。

## 5. 状态、对象与审查方法

- 单文件、无外部依赖。画布按 1600 × 900 等比缩放。每层是独立且稳定的 SVG 组（`data-slice`），持有三枚可变形轮廓、锚点、截面标记和取景框。
- `render(t)` 使用同一秒数计算位置、形态、明暗与可交互状态。播放、暂停、回拖、阶段定位共享时间轴；`requestAnimationFrame` 只负责推进时钟。对象点选只改变展示权重。
- 直接打开 [index.html](index.html) 默认播放一次。空格播放或暂停，左右键回退或前进 0.75 秒；重播回到开头。阶段按钮可直接定位，拖动时间轴可逐帧观察。URL 参数 `?t=15` 可打开并停在指定秒数。「隐藏图注」可检查轮廓、同源标记和三层聚焦能否脱离文字成立。系统启用减少动态效果时，默认停在已建立关联的状态，由观众主动播放或定位。
- 图解中截面的颜色取自正式 Deck 的 `opening.css`：Graph `#819efe`、Assignment `#6ad9a2`、Pipeline `#efb864`；深底、母版尺寸及 Paged Attention 语境保留。视角图标以 Deck 的图形语汇重新画为可内嵌矢量，未导入 P9/P10 的工作台画面。

## 6. 迁移到正式 Deck

1. 先保留两次人工讲述停顿：形成关联约 7 s，侧视结构完整约 18 s。正式演示中可将前进与返回映射到这些稳定状态，再将 24 s 连播留给独立回放。避免 P10 还在解释执行细节时，P11 就自动切进深层。
2. 保留原 Deck 的页面激活、预览与导航职责。当前正式 P11 通过 `ComputeExplorerStory.setActive`、`goToStep` 和 `suspend` 参与父级控制；可在原型与宿主之间加映射，把时钟挂起、恢复和阶段定位接入这些接口。缩略预览固定在 7 s 或 18.65 s。进入真实迁移前再接管标题和播放条。
3. P9 使用 Assignment/Graph/Pipeline 的原生视图与 Task 48 的状态，通过消息与 Deck 同步；P10 从 Device 到任务所在 Block，再到 Task 的逻辑轮次，通过 `ptoDrilldownStory.set(step, {context, animate})` 接收上下文。两页的对象路径和流转可作为迁移锚点。只有在对应字段和映射核实时才用真 ID 取代 A01；不要将 P10 的逻辑 Tick 当作实测时间，或由截面上的几何位置推导调度分配。

## 7. 待验证

- **第一眼的可读性**：隐藏图注后，可以看到三个观察面围绕中心相交、分出截面，再沿轴收拢并逐层定位；仅凭形状不应要求观众准确说出三条关联的业务语义。建议让未看过方案的人静音观看，并在关联形成、侧视稳定两处各复述一句。
- **节奏和投影条件**：24 秒能容纳两幕连续演绎；是否需要缩到 18–20 秒，取决于讲述中是否现场点选 A01。实际会议室有环境光时，需复核被弱化层级的可见度。
- **视觉参考**：本轮未能查看四张参考图的图像内容；[Pinterest 运动参考](https://nl.pinterest.com/pin/835136324702034374/)也未能访问。侧视依据文字要求独立实现。若后续取得图像，可用其核对摄像机关系和节奏，无需复刻材质与形状。

## 浏览器验收

使用本机 Chrome 连续播放至 24 秒，并在 1600 × 900 抓取下列静帧；在 1280 × 720 检查字号、截面方向和控件布局。确认默认自动播放、暂停不前进、重播、回拖、两幕定位、A01 点选、层级引注和减少动态效果路径，未发现脚本异常。
