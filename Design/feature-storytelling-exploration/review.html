业务事实与交互约束

P05 · 从输入坐标到逻辑 Block

  • 固定语义　16 Batch × 8 KV Heads = 128 Tasks。task = batch × 8 + kv_head；block = task % 24。Block b 沿 range(b,128,24) 处理任务，Block 0–7 有 6 个 Task，其余有 5 个。每个 KV Head 对应 5 个 Q Heads。
  • 可抽象表达　输入坐标、Block 容器、位置变换、焦点与同组对象可分别承担叙事。保留 Task ID，使任何入口都能反查来源和去向。
  • 原实现边界　现有关键帧从输入生成 Task、重排至 Block 并下钻。Block 是源码的逻辑执行范围，任务数与空间位置只表达映射关系。
  • 核心交互　从 128 个对象定位一项，核对它的 Batch、KV Head、Block 和组内邻居。

P07 · 从阶段交接到 Slot 周转

  • 固定语义　Task 48 对应 Batch 6 / KV Head 0，默认 3072 tokens，分成 6 Stacks。生产 QK、Softmax 在 T = stack，消费 PV、Accumulate 在 T = stack + 2。总计 8 轮，Slot 取 stack % 3，Stack 0 / 3、1 / 4、2 / 5 分别复用。
  • 固定语义　QK 写 score、Softmax 写 probability、PV 写 partial output。对应三组 READY：QK_READY、SOFTMAX_READY、PV_READY。生产端写入后 SET，消费端通过 WAIT 后读取；累积跨 Stack 更新，最后写出 ctx。
  • 可抽象表达　独立展开一条数据边、交互检查 READY 条件、跟随固定 Slot 推进逻辑 Tick。资源复用线只表示共享地址分组，数据依赖继续沿 transfer 边表达。
  • 原实现边界　现有 Pipeline 用逻辑 Tick 和阶段泳道表达循环位置。阶段间距、实际硬件重叠、持续时间及 WAIT 是否造成 Stall 需要编译或运行证据。
  • 核心交互　逐步推进或尝试消费，明确当前阶段依赖的数据、READY 条件与所在 Slot。

P13 · 从 Sequence Length 到工作划分

  • 固定语义　源常量 BLOCK_SIZE=128、STACK_PAGES=4、STACK_TOKENS=512。Pages=ceil(L/128)，Stacks=ceil(L/512)=ceil(Pages/4)，Ticks=Stacks+2。尾页有效量 (L−1)%128+1。
  • 可抽象表达　连续标尺显示边界与有效量、逐步代入公式、构造边界前后最小差异。输入与假设各自独立保存。
  • 原实现边界　推演 Demo 的当前场景接受 1–3584 整数 tokens，并比较逻辑工作量。该范围来自 Demo 场景，推演结果来自规则计算，实际性能需要运行证据。
  • 核心交互　用户可以改任一输入，也可以套用边界实验。保留对照，显示变化如何传导到 Page、Stack、逻辑轮次和尾部。
