标准结构 vs 内核实际计算过程

右侧内核跟 HuggingFace 参考实现数学上等价，但没有一个算子是照搬的。 变化集中在四件事：把归一化的标量除法推迟到矩阵乘之后、把相邻算子融进同一个 task、 把每个 GEMM 炸成几十个 split-K task、以及把 BF16 精度边界从每层一次收缩到整网两次。 下面按 10 个阶段逐段对照。

代数重排 reorder
数学恒等，但执行位置变了。几乎全部是"延迟除法"：标量因子穿过矩阵乘，挪到下游补乘。
融合 fuse
多个标准算子合进一个 task，中间结果留在寄存器，不走全局内存往返。
并行拆分 split
一个标准算子展开成 N 个并行 task；GEMM 走 split-K + 原子加，注意力走块级负载均衡。
精度边界 precision
dtype 变了。层间残差从 BF16 改为 FP32 承载，只在整网首尾各转一次。

01input_layernorm 代数重排跨层融合精度
标准实现
RMSNorm(x) · γ_in
inv = rsqrt(mean(x²)+ε)
x₁ = (x · inv) ⊙ γ_in
一个融合算子，一次搞定
PyPTO 内核 — 拆成三处
rms_recip×1
只算 inv_rms[b] 这个每行标量，不碰数据。和 QKV 投影并行跑，不再挡住下游。
x⊙γ 来自上一层已就绪
乘 γ_in 这一步在上一层末尾的 dcr_xgamma 里就做完了，作为 normed_in 参数传进来。层 0 由 x_gamma0 单独补。
inv_rms 延后补乘下游
Q/K 在 qk_norm 里补，V 在 rope_qkv 里补。见下方推导。
02q_proj / k_proj / v_proj 并行拆分
标准实现
3 × Linear
q = x₁ @ Wq [16, 5120]
k = x₁ @ Wk [16, 1024]
v = x₁ @ Wv [16, 1024]
PyPTO 内核
q_seed / k_seed / v_seed×3
把累加器清零，供后面的原子加落点。无对应标准算子。
q_proj×50
10 个 N-tile（512 宽）× 5 路 split-K（每路 K=1280），各自 matmul_acc 后原子加进 q_proj。
k_proj / v_proj×10 / ×10
同样 split-K=5，N-tile 只有 2 个（KV hidden = 1024，GQA 8 头）。
03q_norm / k_norm（Qwen3 特有的 per-head QK-Norm） 融合代数重排
标准实现
q_norm(q) · γ_q
按 head_dim=128 做 RMSNorm
k_norm(k) · γ_k
两个独立算子，各读一遍数据
PyPTO 内核
qk_norm×8
每个 KV-head 一个 task，Q 和 K 合并，且 γ 缩放与 rsqrt 归约共用同一次读取—— 原本 16 个 task、每份数据读两遍，现在 8 个 task、读一遍。

这里只算出 head-norm 的倒数标量存起来，真正相乘挪到 rope_qkv。第 01 阶段欠的 inv_rms 在这里补上。

05attention（GQA，causal） 拆成三段QK·softmax·SV 融合
标准实现

无对应标准算子。把 ragged batch 里所有真实 seq-block 压成一张无空洞的工作表 fa_work_table[w] = b·32 + p，让长度倾斜不再造成核间空转。

推导为什么可以把除法推迟

这是全文件最核心的一个变换，出现了两次（前置 norm 一次、后置 norm 一次），但两次的处理方式并不一样。

前置 norm：整个标量都能穿过去

inv_rms 是每行一个标量，矩阵乘是列变换，二者可交换。

标准 
x₁ = (x · inv) ⊙ γ
q  = x₁ @ Wq
内核 
n  = x ⊙ γ          ← 上一层 dcr_xgamma
q' = n @ Wq         ← q_proj
q  = inv · q'        ← qk_norm 里补

成立因为  (inv·n) @ Wq  ≡  inv·(n @ Wq)

额外收获：Q/K 紧接着还要做 per-head QK-Norm，inv_rms 在那个归一化的分子分母里 自行抵消，所以 RoPE 阶段不必再乘它。只有 V 路径需要真正乘上——代码里正是 v_proj[b] · inv_rms_b 这一处。

后置 norm：只有一半能穿过去

γ 沿 K 维分布，被矩阵乘吃掉；标量 inv′ 可以穿，但会撞上非线性。

标准 
x₂ = (h₁ · inv′) ⊙ γ_post
g  = x₂ @ Wg ;  u = x₂ @ Wu
m  = SiLU(g) · u
内核 
γ_post 就地乘  ← residual_rms_cast（K 维，穿不过）
g′ = (h₁⊙γ) @ Wg ; u′ = …
m  = SiLU(inv′·g′) · (inv′·u′)
                    ↑ 必须在 SiLU 之前，它是非线性的

收益：post_rms_reduce（全 hidden 的归约）不再挡在 gate/up 投影前面， 两者可以并行；代价是 silu task 多做一次逐元素缩放。

精度层间进位从 BF16 改成 FP32

这是唯一一处让数值不再与参考实现逐位一致的改动——而且是往更精确的方向偏。

标准 · 每层一次舍入 
embed ─BF16→ L0 ─BF16→ L1 ─BF16→ … ─BF16→ L39 ─BF16→ lm_head
              └─ 层内 FP32 计算，出口截回 BF16 ──┘   共 40 次舍入
内核 · 整网两次转换 
embed ─BF16→ copy_hidden ─FP32→ L0 → L1 → … → L39 ─FP32→ cast_lmhead_in ─BF16→ lm_head
                                └── 残差流全程 FP32 ──┘   共 2 次舍入

注意 normed（x⊙γ）仍然是 BF16——它是矩阵乘的输入，必须是 BF16 才能走 Cube 单元。 变成 FP32 的只有残差流本身。
因此文件的验收标准不是逐位相等，而是 argmax 匹配 + 2% 容忍的 ratio-allclose （rtol=atol=3e-3）——BF16 在数值 1 附近一个 ULP 就有 0.0039，严格 allclose 本来也过不去。

边界没有动的部分

对照时容易误判，先划清楚。

模型结构本身，一个数都没改
  • 40 层 / 40 Q 头 / 8 KV 头 / head_dim 128，hidden 5120，intermediate 17408 —— 与 Qwen3-14B 完全一致
  • GQA 比例 5:1、causal 掩码、RoPE 的 lo/hi 半维旋转方式，都是标准的
  • Qwen3 特有的 per-head QK-Norm 保留（这正是 Qwen3 区别于 Qwen2 的地方）
  • 两处残差、两处 RMSNorm 的拓扑没变，只是被切碎重新分配到不同 task
  • 权重张量的形状与语义一致，只是按 layer_idx 做了堆叠切片
不在这个文件里的部分
  • Embedding 查表 —— 外部传入 BF16 hidden_states [16, 5120]
  • 采样 / argmax —— 内核出 [16, 151936] FP32 logits，host 侧再采样
  • Prefill —— 有一个配对的 prefill 内核在别处；两者共用同一个分页 KV 池，页大小 128
  • final_norm + lm_head 由 rms_lm_head 提供，只在 decode_fwd（整网入口）里接上
