# 照片冲印叙事模式

该模式为同一个 Compute Explorer 提供另一种观察语言。默认仍为计算世界；按钮切换后，Assignment、Pipeline、Graph 及其内部视图立即切换。原始 Python 源码、真实语义图、任务模型、依赖、调度规则和参数编辑模型不被改写。

## 概念映射

| 计算对象 | 叙事表达 | 编号与数量 |
| --- | --- | --- |
| Batch | 顾客 | 顾客序号 = Batch + 1 |
| KV Head | 主题 | 保留主题编号，8 个主题/顾客 |
| Q Head | 匹配子项 | 每张工单固定 5 个子项 |
| Task | 工单 | 保留 Task ID，例如工单 48 |
| Block | 工作小组 | 保留 Block ID；24 个工作小组 |
| Sequence Length / Token | 照片总数 / 照片 | 有效数量来自当前共享参数场景 |
| Page | 标准照片包 | 最多 128 张；面向人的照片包序号 = Page index + 1 |
| Stack | 处理批次 | 最多 4 包、512 张；显示第 index + 1 批 |
| Slot | 周转台位 | 3 个台位，保留 0、1、2 的循环规则 |
| Phase0 | 订单准备 | 准备项、主题、工作小组的逻辑分配 |
| Logical Tick | 流水轮次 | 离散逻辑进度，横向距离不表示真实时间 |
| QK / Softmax | 照片分析与整理 | 前段处理的两道工序 |
| PV / Context Accumulate | 后段加工与成品汇总 | 后段加工的两道工序 |
| READY / SET / WAIT | 交接就绪 / 发出就绪 / 等待就绪 | 逻辑交接，不能推断实际停顿 |

标准订单共有 16 位顾客、128 张工单、24 个工作小组。工单 48 对应 Batch 6，即顾客 7；有效照片 3072 张，24 个标准照片包、6 个处理批次，周转台位依次为 0 → 1 → 2 → 0 → 1 → 2。

将该工单照片数改为 1025 时，现有分区规则推导为 9 包、3 批；最后一包和最后一批均为 1 张有效照片。数量改变后仍属于工单 48、顾客 7，不使用 N 遮蔽身份。增减包/批时沿用现有共享场景对尾包有效数量的保持规则。

## 渲染边界

`js/photo-narrative.js` 集中拥有叙事词汇、编号格式和显式渲染入口 `text`、`html`、`attr`。各视图在原有渲染位置调用这些入口：HTML 模板在插入文档前解析为片段，并注册文本和面向人的属性表达式。动态文本也由同一个入口注册。

切换只重新计算已注册表达式，不扫描已渲染页面、不全局拦截原生 DOM API、不替换整个视图。`data-*` 选择器、模型 ID、API 标识、源码字符串以及 `pre/code` 内容不参与叙事翻译。`data-display-label` 是唯一显式注册的显示属性。SVG text、tspan、title、aria-label、optgroup label 和 tooltip 使用同一入口。

模式状态独立于 Task、共享子对象、活动 Tab、下钻状态、各视图相机、滚动容器和 Inspector 开关。Graph 在模式修订后重新计算图投影，不将语言切换视为首次进入，也不会触发自动适应或重新聚焦。

## Graph 的叙事投影

`js/photo-narrative-graph.js` 产生独立、缓存的四阶段模型，使用已有语义图组件的布局、卡片、边、展开/收起、平移、缩放、图层和 Inspector 机制：

1. 主题匹配：读取匹配条件 → 匹配照片主题 → 形成匹配结果。
2. 筛选去重：筛选入选照片 → 去除重复照片 → 整理打印清单。
3. 打印：准备打印 → 打印照片 → 检查打印结果。
4. 装帧：汇总已打印照片 → 装帧照片 → 整理交付。

这些边表示照片故事内部的流程；它们不替换或伪装成真实计算图依赖。投影声明独立的 `photo-narrative` 来源，使用 `origin: narrative` 标记，Inspector 与顶部说明都明确边界。其节点数量不作为真实执行次数，不应用真实计算图的性能权重和源码跳转。

为维持共享工单与视图选择，四个根阶段采用 qk、softmax、pv、output-norm 的展示锚点；这个映射只用于 UI 导航，不意味着去重、裁剪或打印存在于 attention 算法中。切回计算世界时恢复真实语义模型。Pipeline 沿用真实逻辑调度的形状与交接关系，只把叙事语言投影到显示层；Graph 故事关系与 Pipeline 源码依赖不可混为一谈。

已执行 JavaScript 语法检查；独立叙事模型通过现有 `PTO_SEMANTIC_COMPUTATION_GRAPH.validate` 校验，4 个可展开复合阶段，各含 3 个子步骤。

浏览器验收由主代理进行，覆盖默认计算世界、外部分配、工单 48 下钻、重复切换、参数与尾包、内部流水线及周转复用、Graph 展开/Inspector、返回计算世界。对应截图与最终浏览器结果见本次交付记录。此处不把静态检查记作浏览器验收。

没有真实照片输入、照片像素算法、运行时 trace 或实测性能数据。不得据此声称提速、真实并发、槽位实际占用或真实等待时长。

## 照片主题

冲印模式下 KV Head 0–7 稳定对应：宠物、家人、朋友、旅行、美食、风景、日常、纪念日。该映射只改变显示名称，计算模式和底层编号不变。
