# 面向加速器算子的工作项执行路径与硬件资源联动定位方法

发明专利技术交底初稿 · 2026-11-20

## 1. 技术领域与待解决问题

本方案涉及加速器算子开发工具、编译中间表示分析和交互式调试。以下以 Operator Lens 的任务分配图、计算图和存储落点图为例，说明开发者如何从一个具体工作项追到其执行路径及硬件资源。

加速器算子的同一 Kernel 可以在多个逻辑执行通道中重复处理不同的工作项（Work Item）。对于稀疏注意力，两个工作项即使使用同一份 Kernel 和同一份片上存储分配，也可能读取不同的 KV 数据源、进入不同分支，或只写回初值。开发者选中一块任务后，需要结合任务队列、运行输入、控制流以及编译器分配结果，判断该工作项涉及哪些算子、存储空间和跨核通道。静态编译布局本身保留整份 Kernel 的资源分配，同一个地址还可能被多个中间值复用，单凭地址和源码位置难以确定当前工作项的访问关系。

## 2. 发明构思

系统把**工作项选择**作为路径和资源查询的输入。用户在任务分配图中选中某个工作项，系统解析它在派发队列中的位置与关联输入，求值该工作项的分支条件和访问范围，再把有效路径上的操作同编译后的执行单元、存储分配及跨核通道绑定。三图共用同一工作项上下文。用户切到资源视图时，系统带着已求值的路径定位资源。用户反向点选一个缓冲区时，系统在当前工作项的访问关系中查找对应操作和源码位置。

**交互创新在于一次选择驱动两级推导。** 同一个计算节点或缓冲区随工作项的输入而呈现不同的有效范围、访问类型或关联操作。用户可以从“这一份工作在哪一轮被领取”连续追问到“为什么访问这里”，并回到任务分配图选择另一份工作进行比较。

图 1 为方法流程。任务分配图产生选择上下文，计算图与存储落点图接受同一上下文的分析结果。

```mermaid
flowchart LR
    A[任务分配图选中工作项] --> B[解析队列位置和输入]
    B --> C[求值分支与 Tile 访问范围]
    C --> D[计算图显示当前路径]
    C --> E[根据编译绑定解析资源访问]
    E --> F[存储落点图显示资源与通道]
    F -->|选中缓冲区| G[在当前路径中反查操作和源码]
    G --> D
```

## 3. 数据与处理步骤

### S101 解析选中的工作项

任务分配图的单元关联 Kernel、队列序号、逻辑 Lane 和轮次。系统以编译产物标识、输入快照标识、Rank、Kernel 和队列序号标识一次工作项选择。同一个 Kernel 多次派发时，可加上派发实例标识。系统根据该标识读取队列条目和与分支相关的输入，例如有效块掩码、token 位置、稀疏索引和页表。离线分析可使用保存的输入快照。物理核编号可在有匹配的运行记录时补充。

### S102 推导本工作项的计算路径

系统读取带控制依赖和数据依赖的算子图。使用工作项输入求值影响分支、循环、搬运和 Tile 有效区域的表达式，得到操作实例、前后依赖及其源位置。循环中同一个源码操作可对应多个搬运实例，分别保留段号、行号或流水阶段。对搬运分别记录**参与后续运算的有效范围**和**执行读写的访问范围**。例如被 softmax bias 屏蔽的占位行仍可能发生读取和写入。缺少分支输入时，保留对应路径为「待确定」，连同缺失字段供用户检查。

### S103 关联编译后的资源绑定

一种拟实现方式是在编译快照或编译器生成的映射中，为操作保留可追溯的语义标识，记录拆分、展开和复用前后的对应关系。绑定记录至少包含产物版本、编译后操作、执行角色、访问类型、存储空间及缓冲标识。若产物提供地址和长度，进一步记录相对偏移、分配大小以及可用的布局、子块和管道槽信息。一个源码操作拆成 AIC 矩阵计算、AIV 向量计算或管道操作时，可保留多条绑定。

系统用 S102 的操作实例查询这些绑定，并根据分支条件、Tile 有效形状、内存布局以及编译生成的同步操作得到本工作项的资源访问记录。分配占用和访问范围分别保留。具备足够的布局和范围信息时，可将 Tile 访问换算成存储空间内的字节区间。多个中间值共用一个缓冲时，先按编译操作、访问阶段或已知存活区间保留各自的访问记录，再按资源聚合显示。资源状态可显示为「访问有效数据」「包含占位读写」「仅同步」「已分配且本工作项未访问」或「待确定」。同步状态依赖具体的管道操作，`valid_shape` 为零仅说明该 Tile 的有效数据范围为空。

### S104 同步更新三图并支持反查

任务分配图保留选中的 Lane、轮次和工作项标识。计算图突出求值后的路径及有效行数。存储落点图保留 Kernel 的静态分配作为底图，并突出当前工作项涉及的资源访问及同步关系。选择一个缓冲后，系统将该缓冲的编译绑定同当前工作项的有效操作实例求交，返回关联的操作、源码位置和读写范围。切换视图时保持工作项上下文，切换工作项时按新上下文重新求值。

## 4. qk_pv 实施例

### 4.1 从任务分配单元定位到输入

示例采用 Demo 默认配置。每个 Rank 有 256 个 token，每个 token 对应 5 个稀疏块，形成 1,280 个工作项。`qk_plan` 生成 `qk_order`，将非空块排在前面、空块追加在后。`qk_pv` 由 24 条逻辑 Lane 以轮询步长领取。点中 Lane `l` 的第 `i` 轮后，解析过程如下，编号从 0 开始。

```text
队列位置 q = l + 24 × i
工作项编号 id = qk_order[q]
token t = floor(id / 5)
稀疏块 sb = id mod 5
分支条件 = valid_block_mask[t, sb] > 0
```

下表选取 Rank 0 中同一 token 的三个 Demo 工作项，模拟位置均为 `position = 7`。编号、队列位置和有效行数来自原型生成器。最后一列说明拟实现的落点输出，以及可与编译产物核对的绑定。

| 工作项与选中位置 | 计算路径推导 | 实例级存储落点示例 |
| --- | --- | --- |
| **#0 滑窗块 SB0**。队列 0，Lane 0，轮次 0 | 窗口最多 128 行。此处可见长度为 `min(7 + 1, 128) = 8`，从位置 0 起，位于一个 32 行页内。对照源码，页映射有效时，从原始 KV 成段搬入 8 行，其余 120 行从第 0 行取占位数据。随后执行 QK 矩阵乘、向量侧的缩放与归约、PV 矩阵乘，并写回 `mi/li/oi`。 | 显示原始 KV 的 GM 来源和 AIC 的 L1 目标，分别标记有效段和占位范围。沿有效块路径继续定位 AIC 的矩阵计算存储、AIV 的 UB 工作区以及 AIC 与 AIV 之间的通道。 |
| **#1 压缩块 SB1**。队列 1，Lane 1，轮次 0 | 本块覆盖压缩 Top-k 的前 128 个位置，逐行判断索引。示例有 2 条有效记录，其余 126 条走占位路径。源码使用有效索引及压缩页表计算压缩 KV 的源行，对无效索引从原始 KV 第 0 行取占位数据。后续矩阵乘、归约及写回与有效滑窗块一致。 | 显示两类 GM 来源汇入同一 L1 KV Tile。对有效索引，源行为 `cmp_block_table[请求, floor(slot / 32)] × 32 + slot mod 32`。模拟生成器只给出有效行数，具体源行和地址需要索引、页表及对应布局。 |
| **#2 空块 SB2**。队列 992，Lane 8，轮次 41 | 掩码判定为空，处理逻辑进入初始化分支。依次写回 `mi = −3.0e38`、`li = 0`、`oi = 0`，跳过 KV 拼装、QK/PV 矩阵乘及 softmax 计算链。 | 定位初始化操作所需的本地缓冲与 GM 输出区域。仍须检查编译后空块分支包含的控制与同步操作。计算链对应的静态分配仍可在底图查看。 |

数据与源码依据见 [Demo 数据生成器](../Design/csa-operator-lens/js/lens-data.js#L267) 和 [`qk_pv` 算子源码](../Data/DeepseekV4/deepseek_v4_flash_dspark/decode_sparse_attn_csa.py#L208)。

### 4.2 从一条计算路径追到地址

以滑窗搬运为例，选中计算图中的成段搬运节点后，可将源码的 `gather_row` 与编译产物中 `qk_pv_aic` 的对应操作关联。归档 Pass 36 中，KV Tile 对应 `mem_mat_14`，在 Mat（L1）空间内的分配起始偏移为 **32,768 B**，分配长度为 **131,072 B**。底图显示这一静态区间，路径结果分别标记本示例的 8 行有效数据和 120 行占位写入。在编译布局可以解析时，再显示各次写入对应的字节区间。同一缓冲在压缩块中仍可作为目标，反查结果会指向逐行搬运操作及其来源。关联位置可核对 [Pass 36 的 `qk_pv_aic`](../Data/DeepseekV4/_jit_l3_decode_csa_20260903_010617/passes_dump/36_after_AllocateMemoryAddr.py#L2785)。

在向量侧，归档的 `qk_pv_aiv` 带有 `dual_aiv_dispatch`。第二个 AIV 子块在相应分支中出现 `valid_shape=[0, 0]` 的 Tile，并保有管道取槽和释放操作。这个样本可用于验证存储图能否同时表达「有静态分配」和「对应管道操作仅参与同步」两项事实。上述地址和子块行为来自归档样本。要形成可重复的逐实例结果，需要绑定同一构建的源码、编译产物和输入。[Pass 36 的 `qk_pv_aiv`](../Data/DeepseekV4/_jit_l3_decode_csa_20260903_010617/passes_dump/36_after_AllocateMemoryAddr.py#L2951) · [存储视图数据说明](../Design/csa-operator-lens/js/lens-tile.js#L11)

## 6. 拟保护要点与效果

独立方法的候选特征为 **响应工作项选择，解析该工作项的派发位置及输入，对通用算子图求值以提取实例路径，依据编译绑定求得对应的存储访问和同步关系，并用同一工作项上下文更新任务、计算与资源视图**。可进一步限定多级编译映射、有效区域与占位访问的表达、共享槽位上的实例级反查、缺失输入时的条件状态，以及从逻辑 Lane 补充定位物理核的方式。交互实施例可配图展示从工作项格子下钻到路径、从路径定位缓冲、再从缓冲反查当前操作的三个关键状态。

预期技术效果是**在同一静态分配下判别不同工作项引起的路径与资源访问差异**。可用路径识别正确率、资源访问分类准确率和反查结果一致性评价分析机制，并对照静态联动记录完成相同诊断任务的时间和错判次数。性能提升及诊断用时尚待验证。
