# 大模型推理调优工具 — 功能规划

**定位**：一体化平台（评测选型 + 深度调优 + 生产监控自动调优），面向自己/小团队内部使用。
**原则**：功能求全，工程求精简——能复用开源组件的地方尽量复用，自研精力集中在"把三段打通"这个差异化能力上。

---

## 一、整体架构：三层闭环

```
第一层：横向评测选型（离线，用一次）
第二层：深度调优（半自动，迭代跑）
第三层：生产监控 + 自动调优（在线，持续跑）
        ↓
   共享同一套：数据模型 + 指标定义 + 存储 + 可视化
```

三段共用一套指标口径和存储，是"一体化"真正有价值的关键——否则就是三个互不相干的小工具拼在一起。

---

## 二、模块规划

### P0：基础层（没有这些后面都做不了）

#### 1. 统一指标与数据模型
- 核心指标：
  - TTFT（首 token 延迟）
  - TPOT / ITL（逐 token 延迟）
  - 端到端延迟
  - 吞吐（req/s、tokens/s）
  - GPU 利用率、显存占用
  - KV cache 命中率 / 占用率
- 统一的请求/响应 schema，屏蔽不同引擎 API 差异（多数引擎兼容 OpenAI 格式，但参数、流式返回细节不同）

#### 2. 压测/基准测试引擎
- 支持恒定速率、Poisson 分布、突发流量等多种请求模式
- 支持真实流量回放（trace replay）和合成数据生成（可控输入/输出长度分布）
- **不用从零写**：基于开源库做适配层，比如 LLMPerf（Ray 项目开源）、NVIDIA AIPerf（原 GenAI-Perf），或各引擎自带的 benchmark 脚本（vLLM/SGLang 都自带）——自己维护一个统一入口调用它们，而不是重复实现压测逻辑

#### 3. 多引擎/多硬件适配层
- 抽象出"部署配置"（引擎类型、模型、TP/PP 并行度、量化方式、显卡型号）→ 生成实际启动命令/Docker 配置
- 先支持实际会用的 1-2 个引擎（比如 vLLM + SGLang），做深不做广，后面再扩展

---

### P1：核心调优能力

#### 4. 参数空间探索 / 自动调优
- 关键可调参数：
  - `max_num_seqs`
  - `gpu_memory_utilization`
  - `tensor_parallel_size`
  - KV cache block size
  - 量化方案（AWQ / GPTQ / FP8）
  - chunked prefill 开关
  - prefix caching 开关
  - speculative decoding 配置
- 搜索策略：先用简单网格搜索/随机搜索验证流程通了，再考虑接入贝叶斯优化（直接用现成的 Optuna 库，不自己写优化算法）
- 目标函数需可配置：吞吐最大化 / 延迟 SLA 约束下吞吐最大化 / 单位 token 成本最优

#### 5. Profiling 与瓶颈定位
- Prefill 阶段 vs Decode 阶段耗时拆解
- 三类瓶颈自动归因（先做简单规则判断即可）：
  - compute-bound
  - memory-bound
  - 显存不足导致的排队
  - 规则示例：GPU 利用率高 + 显存打满 → 显存瓶颈；GPU 利用率低 + 延迟高 → 调度或网络瓶颈
- 有余力再接 NVIDIA Nsight / PyTorch Profiler 做 kernel 级分析，初期可跳过

#### 6. 可视化 Dashboard 与对比报告
- 核心图表：不同配置/引擎的吞吐-延迟曲线对比
- 建议直接用 Prometheus + Grafana 承载时序数据和大盘，自己只需把指标埋点打进去，不自研可视化系统

---

### P2：生产闭环（最后做，价值最大也最复杂）

#### 7. 生产监控 + 异常检测
- 接入线上真实 QPS、延迟分布，与 SLA 对比
- 异常检测：延迟突增、吞吐掉底、显存 OOM 风险预警

#### 8. 自动调优闭环
- 检测到流量模式变化（如平均输入长度变长、并发升高）→ 自动触发离线的 P1 模块重新搜参 → 验证后灰度切换配置
- 这是整个平台的"杀手锏"功能，依赖前面模块都稳定后再做，排最后

#### 9. 配置知识库
- 把每次调优结果沉淀为"模型规模 + 硬件 + SLA → 最优配置"的经验库
- 新模型上线时先查库给初始配置，减少重复搜参

---

## 三、给小团队的建议

- **不重复造轮子**：压测执行、优化搜索算法、监控可视化都有成熟开源方案（LLMPerf/AIPerf、Optuna、Prometheus+Grafana），自研代码集中在"胶水层"——统一指标定义、多引擎适配、配置知识库这些别人没有的部分。
- **MVP 范围建议**：先打通 P0 + 模块 4/5/6，即能对 1-2 个引擎跑压测、搜出较优参数、出一张吞吐-延迟对比图。这一步大概率就能覆盖 80% 的日常调优需求。生产闭环（P2）等确认前面模块真的常用后再投入。
